## ⚙️ 2. Как KubeJS обрабатывает локализации

KubeJS работает как виртуальный ресурспак высшего приоритета. Чтобы перевести предмет, блок, категорию или интерфейс любого мода:
1. Определяется пространство имён (Namespace мода): например, `moreminecarts`, `shippingbin`, `society`, `portable_blueprints`, `dialog`.
2. Перевод помещается в JSON-файл по пути:
   `D:\ModrinthApp\profiles\Society_ Sunlit Valley\kubejs\assets\<namespace>\lang\ru_ru.json`
3. В игре перевод применяется мгновенно по нажатию комбинации **`F3 + T`** (перезагрузка ресурсов клиента без перезапуска игры).

## 🛠️ 3. Пошаговый алгоритм: Как делать единичные правки предметов

Когда пользователь просит перевести или изменить название конкретного предмета (например, `мод:предмет` $\rightarrow$ `Новое Название`):

### Шаг 1: Найти Namespace и ключи локализации
В игре внедрена удобная команда-инспектор:
- Игрок держит предмет в руке и пишет: `/trans` (или `/translate`).
- В чате появляется карточка с кнопкой `[📋 НАЖМИТЕ ЗДЕСЬ, ЧТОБЫ СКОПИРОВАТЬ ДЛЯ ИИ]`.
- При нажатии в буфер обмена копируется готовый JSON:
  `"block.moreminecarts.glass_cactus": "Vitric Cactus"`

Ключи в Minecraft строятся по стандарту:
- Предмет: `item.<namespace>.<item_id>`
- Блок: `block.<namespace>.<block_id>`
- Подсказка: `tooltip.<namespace>.<id>`

*(Если точный ключ неизвестен, выполните поиск в `kubejs/assets/<namespace>/lang/en_us.json` или в файлах мода).*

### Шаг 2: Внести правку в `apply_requested_translations.js` (или соответствующий модуль)
Добавьте ключ в соответствующий словарь скрипта [`translations/overrides/apply_requested_translations.js`](file:///c:/Users/Foxi8/OneDrive/Рабочий%20стол/СозданиеПеревода/translations/overrides/apply_requested_translations.js):

```javascript
// Пример добавления перевода для предмета:
const moreminecartsUpdates = {
    "block.moreminecarts.glass_cactus": "Кристаллический кактус",
    "item.moreminecarts.glass_cactus": "Кристаллический кактус",
    // ...
};
```

### Шаг 3: Если предмет использует NBT (динамические предметы)
Если несколько предметов имеют один и тот же базовый ID, но отличаются NBT-данными (как `society:invitation` или `society:villager_home`):
- Обычный `ru_ru.json` переведёт только общее имя для всех.
- Для динамических имён используйте клиентский скрипт KubeJS:
  [`kubejs_scripts/client/invitationTooltips.js`](file:///c:/Users/Foxi8/OneDrive/Рабочий%20стол/СозданиеПеревода/kubejs_scripts/client/invitationTooltips.js):
  ```javascript
  tooltip.addAdvanced("namespace:item_id", (item, advanced, text) => {
      // Считывание NBT и замена заголовка:
      text.set(0, Text.of("Новое Название").color("#FF5555"));
      text.add(1, Text.of("Описание/подсказка").gray());
  });
  ```

### Шаг 4: Выполнить автоматическую синхронизацию
Запустите команду:
```bash
node ./sync_all_to_game.js
```
Скрипт автоматически обновит все локальные JSON, скопирует их в профиль игры и установит скрипты KubeJS.

### Шаг 5: Напомнить пользователю про `F3 + T`
После выполнения синхронизации всегда напоминайте пользователю нажать **`F3 + T`** в запущенной игре.

## 🗂️ 5. Архитектура и регламент работы с задачами (`tasks/`)

Для поддержания идеального порядка в проекте каждая нетривиальная задача (аудит предметов, генерация описаний, перевод механик, FTB Quests) ведётся в изолированной папке: `tasks/<имя_задачи>/`.

### 📂 5.1. Структура папки задачи:
```
tasks/<имя_задачи>/
├── TASK.md                     # Описание задачи, требования, формат и критерии приёмки
├── new_translate               # Рабочий файл согласования: визуальный макет и строки для правок
├── audit_results.md            # Сводная таблица аудита кода, шансы дропа и сводка
└── scripts/                    # Локальные скрипты, специфичные для данной задачи
    ├── audit_<name>.py         # Скрипт парсинга лут-таблиц, KubeJS и магазинов
    └── apply_and_sync.py       # Скрипт пакетного обновления JSON-файлов перевода и верификации
```

### 🔄 5.2. Жизненный цикл задачи и обязательная верификация:
1. **Постановка задачи (`TASK.md`)**: Формулируются цели, правила форматирования (например, `\n\n§8...`) и список целевых предметов/ключей.
2. **Аудит кода и лут-таблиц (`scripts/audit_*.py`)**: Скрипт сканирует директории `game_data/` и `D:\ModrinthApp\profiles\...\kubejs\` (дропы, шансы, спавнеры, магазины, призовые автоматы, дружба NPC).
3. **Фиксация результатов (`audit_results.md`)**: Формируется наглядная таблица с механикой получения каждого предмета.
4. **Согласование перевода (`new_translate`)**: Генерация файла `new_translate` с визуальным шаблоном (как выглядит в игре) и точными строками. Пользователь вносит правки в шаблон или строки.
5. **Локальный скрипт применения и синхронизации (`scripts/apply_and_sync.py`)**: Скрипт напрямую обновляет рабочие языковые файлы в `translations/` и синхронизирует их с `D:\ModrinthApp\profiles\...\kubejs\assets\...`.
6. **ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА ФАЙЛА ИГРЫ (Verification Assertion)**:
   - **СТРОГОЕ ПРАВИЛО ДЛЯ ИИ**: Перед тем как писать пользователю «Нажмите F3 + T», ИИ **ОБЯЗАН** программно прочитать изменённые ключи напрямую из `D:\ModrinthApp\profiles\...\ru_ru.json` и вывести подтверждённые значения. Это на 100% исключает ложные отчёты о синхронизации.
7. **Общая синхронизация**: Запуск `node ./sync_all_to_game.js` и QA-проверка `python tools/validate_qa.py`.

### 💡 5.3. Преимущества локального хранения скриптов в `tasks/`:
- **Чистота глобального репозитория**: Временные и узкоспециализированные скрипты не захламляют папку `tools/`.
- **Локальная автономность**: Внутри каждой задачи есть свой собственный скрипт вставки и проверки, не зависящий от глобальных скриптов.
- **Воспроизводимость**: При обновлении версии модов или сборки можно заново запустить `audit_*.py` из папки задачи и быстро увидеть все изменения в балансе или пулах наград.
- **Прозрачность для пользователя**: Пользователь всегда видит точные цифры и исходный код анализа.

## ⚙️ 6. Технические особенности KubeJS, Candlelight и персистентности данных

### 📜 6.1. Лимиты GUI записок Candlelight (`candlelight:note_paper_written`):
- Записка Candlelight — это **одностраничный лист** фиксированного размера: ширина `114px`, максимальная высота `128px` (~10–11 строк текста).
- Текст длиннее 10–12 строк **не переносится на новую страницу, а визуально обрезается за нижней рамкой листа**.
- **Требование**: Тексты больничных записок и квитанций должны быть лаконичными (6–8 строк суммарно), без избыточных пустых строк `\n\n`.
- **Безопасная генерация NBT**: Никогда не склеивать строковый SNBT вручную (ломается на кавычках вроде `Harvey's`). Передавать прямой NBT-объект:
  ```javascript
  Item.of("candlelight:note_paper_written", {
    author: String(author),
    text: [String(text)],
    title: String(title)
  });
  ```

### 🌐 6.2. Серверная локализация KubeJS:
- Вызов `Text.translatable(key).getString()` на сервере **не выполняет перевод**, так как сервер Minecraft не загружает клиентские языковые файлы (`ru_ru.json`), и возвращает сырой ключ (`society.some_key`).
- Для записи текста в NBT или передачи в EmbersTextAPI/чат необходимо вызывать `.toJson()`:
  ```javascript
  let noteText = Text.translatable("society.hospital_receipt.note.paid", `${visits}`, Text.translatable(quoteKey), `${fee}`, `${total}`).toJson();
  ```
  Клиент Minecraft самостоятельно распарсит JSON и переведёт все внутренние компоненты на язык игрока.

### 💾 6.3. Персистентность NBT при смерти игрока:
- В Minecraft Forge / KubeJS данные `player.persistentData` привязаны к сущности игрока и **сбрасываются при смерти/возрождении**.
- Любые долгосрочные данные персонажа (счётчики визитов/смертей, накопительные суммы расходов, долги) необходимо сохранять в постоянное хранилище мира:
  ```javascript
  const UUID = player.getUuid().toString();
  if (!server.persistentData.hospitalVisits) server.persistentData.hospitalVisits = {};
  server.persistentData.hospitalVisits[UUID] = (server.persistentData.hospitalVisits[UUID] || 0) + 1;
  ```
  Данные `server.persistentData` автоматически сохраняются в `level.dat` и гарантированно работают как в одиночном мире, так и на выделенном сервере.

### 🪙 6.4. Стандарт символов валюты:
- Макрос `:coin:` парсится только модулем книг *Patchouli*.
- В чате, HUD (EmbersTextAPI), тултипах и записках стандартным символом монеты для сборки является **`§e●`** (`U+25CF` жёлтого цвета).

## 📝 7. Регламент работы с файлом согласования `new_translate`

При переводе квестов FTB Quests, тултипов, книг, записок или диалогов ИИ **ОБЯЗАН** сформировать файл `tasks/<имя_задачи>/new_translate` (или `.md`), содержащий два обязательных блока:

### 🎨 Блок 1: Визуальный шаблон (Как это выглядит в игре)
Отображает итоговую вёрстку с форматированием, цветовой разметкой (`&6`, `§e`), переносами строк и постраничным разделением (`{@pagebreak}`).
```markdown
### 📖 Страница 1 (FTB Quests):
> **Вручение подарков**
> 
> Укрепление связей с жителями поможет им чувствовать себя как дома!
> Нажмите **Shift + ПКМ** по жителю, чтобы дарить подарок раз в 4 дня.

### 📖 Страница 2 (после перелистывания `>`):
> **★ Категории подарков (100 очков = 1 ♥):**
> • `💖 Любимый:` **+40 очков**
> • `👍 Нравится:` **+25 очков**
```

### 🔤 Блок 2: Строки и ключи для изменения
Точные строки JSON/SNBT/JS, готовые к точечному редактированию:
```json
{
  "ftbquests.chapter.getting_started.quest3E08F21BA8F69499.title": "Вручение подарков",
  "ftbquests.chapter.getting_started.quest3E08F21BA8F69499.description1": "Укрепление связей с жителями поможет им чувствовать себя в вашем городке как дома!",
  "ftbquests.chapter.getting_started.quest3E08F21BA8F69499.description2": "Нажмите &6Shift + ПКМ&r по жителю с предметом в руке, чтобы вручить подарок (кулдаун — &61 раз в 4 дня&r)."
}
```

### ✏️ Принцип взаимодействия и динамической синхронизации:
- Пользователь может отредактировать либо **визуальный макет** (итоговую страницу), либо **конкретные строки перевода**.
- **Динамический парсинг**: Скрипты задачи (`apply_and_sync.py`) **ОБЯЗАНЫ считывать строки и JSON напрямую из `new_translate`**, а не содержать захардкоженные строки. Это исключает откат пользовательских правок при повторной синхронизации.
- **Двусторонняя синхронность**: При изменении строк в Блоке 2 агент автоматически обновляет визуальный макет в Блоке 1, и наоборот.

## 🛡️ 9. Безопасность и защита структуры FTB Quests (*.snbt)

При локализации и форматировании квестов (`{@pagebreak}`, многостраничные описания, добавление тасок) действуют строгие правила защиты:

1. **Запрет нестрогих регулярных выражений**:
   Запрещено использовать жадные паттерны вида `description:\s*\[[\s\S]*?` при обновлении SNBT. Поиск квеста должен производиться строго по уникальному ID квеста: `id: "<QID>"`.
2. **Обязательное резервное копирование**:
   Перед записью любых изменений в файл `config/ftbquests/quests/chapters/*.snbt` скрипт ОБЯЗАН создать копию `<chapter>.snbt.bak`.
3. **Контроль инвариантов (Количество квестов и Размер файла)**:
   После модификации скрипт программно проверяет:
   - Количество объектов `id: "..."` (не должно уменьшаться).
   - Размер файла в байтах (не должен критически падать).
   - Если проверка не пройдена — файл немедленно восстанавливается из `.bak`, и выполнение прерывается с ошибкой.
