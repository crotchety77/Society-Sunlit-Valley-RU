Продолжаем разработку Guide Book.

Сейчас не пиши пользовательское описание всех интерактивных блоков. Перейди на следующий исследовательский уровень: построение архитектуры интерактивных блоков и их классификация.

Используй уже созданный `Radar` как исходную карту обнаруженных объектов, но не считай его доказательством механики.

Сначала классифицируй обнаруженные интерактивные блоки по типу механики:

* Worker Stations
* Worker Infrastructure
* Production / Processing
* Storage / Logistics
* Progression / Unlock
* Pokemon Interaction
* Special / Ritual
* Utility / Minigame
* прочие категории, если они действительно нужны

Для каждого объекта определи:
`mod → registry ID → Block class → BlockEntity class → связанные рецепты → KubeJS-скрипты → конфигурация → FTB Quests → связанные предметы → связанные Pokémon → зависимости от других механик`.

Особое внимание удели `cobblemon_farmers-2.4-all.jar`.

Исследуй архитектуру:

`StationBaseBlockEntity`
→ общая логика работников
→ специализированные BlockEntity
→ специализированные Block
→ рецепты
→ Pokémon
→ характеристики Pokémon
→ модификаторы
→ производство.

Не ограничивайся перечислением классов. Найди реальные связи между ними.

Первой глубоко исследуй `StationBaseBlockEntity`.

Нужно установить:

* как хранится назначенный Pokémon;
* как определяется работник;
* как проверяется допустимость Pokémon;
* какие характеристики используются;
* как рассчитывается эффективность;
* как работает таймер/рабочий цикл;
* как определяется скорость;
* как определяется производство;
* как работает радиус;
* как работают worker slots;
* как сохраняется состояние;
* какие есть общие модификаторы;
* какие части логики переиспользуются всеми станциями;
* какие части переопределяются специализированными станциями.

Затем сравни:

`GardeningStationBlockEntity`
`RanchingStationBlockEntity`
`CraftStationBlockEntity`
`MysteryMineBlockEntity`
`EnergyPylonBlockEntity`
`CrystalBallBlockEntity`

Отдельно зафиксируй, какие механики являются общими для всех Worker Stations, а какие уникальны для конкретной станции.

Создай/обнови `.md` файлы:

`interactive-blocks/index.md`
`interactive-blocks/cobblemon-farmers/architecture.md`
`interactive-blocks/cobblemon-farmers/station-base.md`
`interactive-blocks/cobblemon-farmers/stations.md`

Также создай `interactive-blocks/cobblemon-farmers/open-questions.md`.

Для каждого важного вывода обязательно укажи источник: класс, путь в JAR, JSON, KubeJS, конфигурацию или другой конкретный источник.

Разделяй:

FACT — непосредственно подтверждено источником.
DERIVED — математически или логически выведено из подтверждённых данных.
INFERRED — предположение.
TEST REQUIRED — требуется проверка в игре.
UNKNOWN — данных недостаточно.

Не используй предыдущие ответы как доказательство.

В конце отчёта укажи:

что удалось доказать;
какие предыдущие утверждения оказались неверными или неподтверждёнными;
какие общие классы и зависимости обнаружены;
какие вопросы остались открытыми;
какую следующую конкретную ветку следует исследовать.

Главная цель этой итерации — не увеличить количество текста Guide Book, а понять архитектуру Worker System настолько глубоко, чтобы последующее описание Gardening/Ranching/Craft/Mystery Mine строилось на общей модели, а не независимо друг от друга.
