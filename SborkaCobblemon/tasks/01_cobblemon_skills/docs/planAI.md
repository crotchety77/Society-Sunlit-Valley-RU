# 📘 Регламент глубокого аудита механик и создания Базы Знаний (Cobblemon)

Настоящий регламент определяет стандарт проведения технического реверс-инжиниринга, фактчекинга и создания интерактивной базы знаний (Guide Book) по механикам сборки **Society Sunlit Cobblemon** (`cobblemon_farmers`, `sunlit_cobblemon`, `society_skills`, KubeJS-системы).

---

## 🎯 1. Главный принцип аудита

> **«Сначала доказать факт в коде и формулах — затем составить практическое руководство для игрока.»**

* **Никаких догадок:** Все радиусы, шансы, множители и таймеры извлекаются напрямую из скомпилированного байткода Forge `.jar` (`javap`), JSON-датапаков и KubeJS-скриптов.
* **Сквозная доступность (Provenance Check):** Проверять предметы по `globalRemovedItems.js` и `removeRecipes.js` перед описанием их получения.
* **Разделение факта и расчёта:** Чётко отделять инструкцию байткода от производной математики.

## 📋 3. «Золотой стандарт» каждого документа (4 обязательных блока)

Каждый файл в архиве строится строго по 4-частной структуре:

```markdown
# 🏷️ [Название блока / Интерактивной механики]

> **Мод / Исходники:** класс .jar / скрипт KubeJS / JSON-рецепт
> **Статус проверки:** 🟢 100% подтверждено байткодом и кодом сборки

---

## 1. 🏗️ Суть механики, крафт и интерфейс
- Назначение блока и принцип работы.
- Точный рецепт крафта (схема сетки верстака).
- Слоты интерфейса (Сырьё / Результат / Работник / Настройки).
- Условия размещения и питания.

---

## 2. 🧠 Формулы и математика (Реверс-инжиниринг)
- Требования к типу покемона (`PokeUtils.validWorkerType`).
- Формула скорости работы (`SpeedModifier` / `SPECIAL_ATTACK`, `ATTACK`, `SPEED`...).
- Формула зоны действия (`AoeRadius` / `HP`, `SPEED`...).
- Формула шанса мульти-дропа (`MultChance`).
- Эффект Шайни-покемона (`isShiny ? 2.0 : 1.0`).
- Влияние Дружбы (`Friendship`) и уровня.
- Технические исключения (например: запрет ускорения Ранчо пилонами).

---

## 3. 🥇 Практический тир-лист и брейкпоинты
- Таблица лучших покемонов для блока (Вид / Тип / Профильный стат / Почему именно он).
- Брейкпоинты статов (пороги 128, 250, 255 для достижения макс. множителей).
- Рекомендации по прокачке IV/EV и витаминам.

---

## 4. 🔄 Автоматизация и синергии на базе
- Схемы подачи ресурсов и отгрузки готовой продукции (воронки, трубы).
- Синергии с Пилонами энергии и соседними станциями.
- Замкнутые производственные цепочки без участия игрока.
```

## ⚙️ 4. Технический пайплайн исследования (3 шага)

```mermaid
flowchart LR
    A[1. Извлечение байткода .jar / KubeJS] --> B[2. Сверка доступности и рецептов]
    B --> C[3. Запись гайда в .md архив]
```

### Шаг 1. Локализация и декомпиляция байткода
1. Извлечь `.class` файлы из мода `mods/cobblemon_farmers-*.jar`.
2. Запустить дизассемблер: `javap -p -c -constants <BlockEntity>.class`.
3. Найти ключевые методы:
   * `tick(...)` — логика каждого тика, таймеры `progress++`, сброс условий.
   * `fetchSpeedModifier(...)` — расчёт множителя скорости по статам.
   * `fetchAoeRadius(...)` — расчёт радиуса Манхэттена / зоны влияния.
   * `fetchMultChance(...)` — шанс дополнительного дропа.
   * `canProcess(...)` — проверка входов, рецептов и совместимости.

### Шаг 2. Сверка с конфигурацией сборки (Provenance Check)
1. Проверить рецепты в `kubejs/server_scripts/cobblemon/cobbleWorkersRecipes.js`.
2. Проверить `globalRemovedItems.js` и `removeRecipes.js` на предмет вырезанных предметов.
3. Проверить интеграцию с FTB Quests и ветками Puffish Skills.

### Шаг 3. Сохранение в базу знаний
Записать итоговый документ в `SborkaCobblemon/tasks/01_cobblemon_skills/docs/XX_NAME.md`.
